## 后续发布与清理

1. 每次发布仍生成独立的新版本目录，完成完整性验证后再切换 `current.json`；不要覆盖已发布版本。
2. 确认新版本可运行、测试通过，并考虑仍打开旧页面的客户端；在线更新时可以暂留上一版本作为过渡。
3. 清理前先提交或外部归档旧发布。检查测试/维护入口有无新增的固定版本依赖。
4. 只删除确认不再需要的历史目录，不删除当前指针引用目录；删除前后验证当前指针原始字节、manifest 哈希、完整文件列表及每个资源哈希。
5. 不增加“仅允许 integration-014”的永久 Git 忽略规则，以免下一次发布被意外排除。

如需提取本次清理的历史包，可按需从提交 `9fbc0b0` 恢复指定目录，例如：

```powershell
git restore --source=9fbc0b0 -- assets/sect3d/integration-013
```

该操作只恢复目录，不激活旧版本。不要为了回退直接手工拼改清单哈希；正式版本切换应走既有校验流程。
