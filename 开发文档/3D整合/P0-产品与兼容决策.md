# P0 产品与兼容决策

## 已冻结的实施默认值

采用主计划13章：git为唯一业务宿主；直接ESM容器化；3D默认关闭；Gal不请求3D模型；先藏经阁；11业务子地点/厢房不开放；B/C/I动态图集，其余静态人物卡或同角色列表fallback；保留displayNpcs实际选择的最多3人；保持两主题现有动作差异；无可信时分时daytime=14/night=22；low为无电影后期/无实时阴影/DPR≤1；失败同地点2D回退；原appId、origin和插件不变。

## 用户确认的外部条件

- 真机/兼容签名稍后提供。当前adb无设备，任何真机性能、原生分享、用户覆盖升级不得记PASS。
- 只使用本地模拟API；不读取/消耗真实API配置，不把真实API连通性记PASS。
- 允许继续实现和自动化，不以外部条件不足中断所有开发；阶段报告须区分实现、自动化结果、未执行的人工门槛。

## 小范围工程细化

1. 为防不同构建run共享写入，导入资源使用 `.scene3d-work/<runId>/resources`，不是固定 `scene3d/resources`；产物仍为 `assets/sect3d/<buildId>`，sourceManifest与run.json固定输入。
2. Windows npm.cmd内部Node与shell Node不一致。当前采用shell `node`显式执行本机npm-cli.js；记录真实Node24.9.0与npm10.9.2，不改全局ExecutionPolicy。
3. 初始复核/测试命令仅在隔离BrowserContext和loopback测试server工作，禁止清真实profile/应用数据。完整原2D快照位于 `.scene3d-work/baseline-original/game`，不再修改它。
4. 工时不再沿用旧19–31人日作为承诺。按测试底座、提取/桥接、NPC/菜单、状态入口、生产验包、真机/签名/灰度和缺陷复测分别记录实际完成度。

## 差异授权规则

业务概率、显示子集访问能力、异常旧档清洗、动作成本、存档格式、原生身份或用户现网发布不在自动顺手修改范围。新的业务差异须独立提出确认；只读通知、DOM恢复协调、锚点和输入隔离按主计划实施。
