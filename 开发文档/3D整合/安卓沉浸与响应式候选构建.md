# 安卓沉浸与响应式候选：隔离构建准备

本说明支持分阶段执行：已获准先创建全新 run 并执行 `run-record → import-assets → build`，只生成该 run 资源；禁止 publish、切换 current 或 prepare/freeze 宿主。UI 可继续旧版本回归。待维护者另行通知，再对同一 run 执行 `publish-assets → verify-web → 打包APK.ps1`，不得因资源 build 完成自行进入后续阶段。

每个资源经历输入 hash → www expectation → Android staging exact set/hash → APK ZIP exact set/hash。`tests/scene3d/apk-unit.mjs` 新测试确认四个资源的字节/映射/清单一致，额外根资源不会自授权，缺失和篡改会被拒绝。测试使用 OS 临时目录的合成项目，不冻结或构建真实项目。

## 旧版 Android 键盘与全屏标志复核

运行主题 `AppTheme.NoActionBar` 必须 `android:windowFullscreen=false`，仅启动主题保留 true。Activity 每次恢复沉浸时先 `clearFlags(FLAG_FULLSCREEN)`，再设 edge-to-edge 并调用 InsetsController 隐藏 systemBars。原因是 Window 的 `FLAG_FULLSCREEN` 会禁用 adjustResize，可能令 API24–29 的兼容 IME Insets 无法可靠更新。

已用本机实际 AndroidX core 1.17.0 runtime jar 的 `javap -c -p` 核验：`WindowInsetsControllerCompat.Impl20.hideForType(STATUS_BARS)` 只设置 View 的 `SYSTEM_UI_FLAG_FULLSCREEN`（4），不会添加 Window 的 `FLAG_FULLSCREEN`（1024）。旧 `WindowInsetsCompat.Impl20` 对 IME 的推导先使用 systemWindowInsets/rootStableInsets，再回退 rootViewVisibleInsets。两个同名 fullscreen 概念不能混用；无需另造 global-layout 高度阈值猜测或牺牲沉浸来常驻状态栏。

实现说明可参照 [AndroidX controller 源码](https://raw.githubusercontent.com/androidx/androidx/androidx-main/core/core/src/main/java/androidx/core/view/WindowInsetsControllerCompat.java)；版本结论以上述本机锁定 1.17.0 字节码为准，而非直接假定 main 分支等于锁定版本。SDK36.1 本地 `android/view/WindowManager.java` 的 FLAG_FULLSCREEN 文档也明确记录忽略 adjustResize。

`tests/scene3d/native-immersive-unit.mjs` 提供4项静态契约：launch/runtime 区分、恢复时先清 flag 再 hide、IME-only padding/关闭恢复及 cutout 透传、方向策略保持。静态契约和 Java/资源编译不能证明真机 IME 行为；当前无 adb 设备，仍需 API24–29 和 API30+ 键盘开关实测。

## 构建前置与边界

1. 等所有 UI/原生/构建脚本及锁文件停止编辑；四个新增资源存在，引用路径正确。页面 `viewport-fit=cover` 与控件 safe-area 由 UI 修改负责。
2. 检查完整 `git status --short` 和 `git -c core.whitespace=cr-at-eol diff --check`，保留其他人的改动，不 checkout/reset。构建不强制 clean，但所有未提交和 untracked 输入必须经过审核。现有 HTML 含混合 CRLF，使用上述单次 `core.whitespace=cr-at-eol` 检查避免行尾 CR 假阳性；不修改全局 Git 配置，不批量统一源文件换行。
3. 使用全新且从未存在的 runId/buildId。不复用 integration-015、不手改历史 run 的冻结字段，不删除失败 run 再重试。
4. Node >=22.12。此机器显式 `C:\Program Files\nodejs\node.exe` 为 22.17.1；PATH 的 node 是 Harness shim，目前返回 24.9.0。建议以下所有构建固定同一显式 Node 和 npm CLI。
5. JDK21：`D:\AS\jbr`（21.0.10）；SDK36：`C:\Users\xpeng\AppData\Local\Android\Sdk`，须有 platform android-36、稳定 build-tools/apksigner、已接受许可证。Gradle wrapper/Maven/npm 首次下载需联网；依赖齐全时可缓存命中。一键脚本不强制 offline。
6. `scene3d` 的 npm 依赖必须与其 lock 匹配；独立 APK 副本由一键脚本自己执行 npm ci。不能复制源 apk 的 node_modules 或 local.properties 替代隔离依赖安装。
7. 当前公开 pointer 是 integration-015，其 run 使用资源源 `.scene3d-work/pro-update-baseline-007c/pro` 和同目录 `source-manifest.json`。准备调查已只读校验该旧 run 的冻结配置/锁/清单摘要及清单中的全部 32 项资源 bytes/hash，均通过。继续沿用这份既有冻结资源源，**不是**旧交付文档的 baseline-original/P0 清单；不重新运行 freeze-baseline 或 snapshot-pro-update。
8. publish-assets 会修改工程的 `assets/sect3d/current.json`，不是纯临时操作。等待绑定旧 buildId 的浏览器测试结束，并确认允许切换 pointer。
9. 源 `apk/www`、源 Android generated assets、已有 APK 不作为临时输出；完整构建只写新 run 的 apk-copy。沉浸配置必须通过副本 cap sync 带入，不能直接对源 native 运行 assemble 使用旧 assets。
10. 产物为开发 debug APK：应用 ID `com.jihaitang.jxz`、versionCode=4/versionName=1.3 保持不变。签名验证不意味着正式签名或可覆盖用户旧版；本步骤不安装设备、不清数据、不发布上线。

## 只检查，不构建

在项目根执行（UI 稳定后再作最终检查）：

```powershell
$Node = 'C:\Program Files\nodejs\node.exe'
& $Node --check scene3d/scripts/prepare-apk.mjs
if ($LASTEXITCODE -ne 0) { throw 'Mapping syntax failed' }
& $Node --test tests/scene3d/apk-unit.mjs tests/scene3d/native-immersive-unit.mjs
if ($LASTEXITCODE -ne 0) { throw 'APK mapping tests failed' }
git -c core.whitespace=cr-at-eol diff --check
if ($LASTEXITCODE -ne 0) { throw 'Resolve/review whitespace errors before freezing' }
```

## 批准后：完整新 run + 一键 native 构建

以下整段只供维护者确认 UI 完成并批准开始之后执行。每个外部命令失败即停止。工作目录须为 `E:\JJBurst\git`；不要先手动 prepare-apk 再运行一键脚本（会因副本已存在而失败）。

```powershell
$ErrorActionPreference = 'Stop'
$Root = 'E:\JJBurst\git'
if ((Get-Location).Path -ne $Root) { throw 'Run from E:\JJBurst\git' }
$Node = 'C:\Program Files\nodejs\node.exe'
$Npm = 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js'
$Java = 'D:\AS\jbr'
$Sdk = 'C:\Users\xpeng\AppData\Local\Android\Sdk'
$SourceRoot = Join-Path $Root '.scene3d-work\pro-update-baseline-007c\pro'
$SourceManifest = Join-Path $Root '.scene3d-work\pro-update-baseline-007c\source-manifest.json'
$RunId = 'immersive-responsive-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
$RunDir = Join-Path $Root ".scene3d-work\$RunId"
$RunRecord = Join-Path $RunDir 'run.json'
if (Test-Path -LiteralPath $RunDir) { throw 'Run already exists; choose another ID' }
if (Test-Path -LiteralPath (Join-Path $Root "assets\sect3d\$RunId")) { throw 'Build ID already published' }
foreach ($Required in @($Node, $Npm, "$Java\bin\java.exe", "$Sdk\platforms\android-36\android.jar", $SourceRoot, $SourceManifest, 'module\game-styles-dialogs.css', 'module\game-dialogs.js', 'ui\settings-dialogs.css', 'secondary-pages-responsive.css')) {
    if (-not (Test-Path -LiteralPath $Required)) { throw "Missing prerequisite: $Required" }
}
function Invoke-CheckedNode([string[]]$Arguments) {
    & $Node @Arguments
    if ($LASTEXITCODE -ne 0) { throw "Node command failed: $($Arguments -join ' ')" }
}

# Existing scene3d dependencies must be checked against the lock first.
# Do NOT npm ci in the source scene3d while browser tests use its dependencies.
# If installation is needed, prepare a separately approved dependency copy.
# The native build script performs npm ci only inside its isolated apk-copy.
Invoke-CheckedNode -Arguments @('--test', 'tests/scene3d/apk-unit.mjs', 'tests/scene3d/native-immersive-unit.mjs')

# New immutable run configuration; no manual editing of steps/status/hashes.
Invoke-CheckedNode -Arguments @(
    'scene3d/scripts/run-record.mjs', "--runRecord=$RunRecord",
    "--runId=$RunId", "--buildId=$RunId", "--projectRoot=$Root",
    "--sourceRoot=$SourceRoot", "--sourceManifest=$SourceManifest",
    "--resourceRoot=$RunDir\resources", "--releaseDir=$RunDir\release",
    "--publishRoot=$Root\assets\sect3d"
)
Invoke-CheckedNode -Arguments @('scene3d/scripts/import-assets.mjs', "--runRecord=$RunRecord")
Invoke-CheckedNode -Arguments @('scene3d/scripts/build.mjs', "--runRecord=$RunRecord")
# This step updates the public pointer; coordinate with any ongoing browser tests.
Invoke-CheckedNode -Arguments @('scene3d/scripts/publish-assets.mjs', "--runRecord=$RunRecord")
Invoke-CheckedNode -Arguments @('scene3d/scripts/verify-web.mjs', "--runRecord=$RunRecord")

# First prepare/freeze of the complete host/native inputs happens inside this script.
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File (Join-Path $Root '打包APK.ps1') `
    -RunRecord $RunRecord -JavaHome $Java -AndroidSdk $Sdk -NodePath $Node -NpmCli $Npm
if ($LASTEXITCODE -ne 0) { throw 'Isolated APK build failed; keep this run for diagnosis' }
```

一键脚本按序执行：

`prepare:apk → 副本 npm ci → 副本 apk/build.js --runRecord=... → cap sync android → verify:staging → gradlew --no-daemon assembleDebug → verify:apk → apksigner verify → 独占复制候选并对比 SHA256`。

所有参数中 `--runRecord` 是 Node 脚本的第一个参数，不依赖当前目录猜测 latest。run 初始化冻结资源源路径/清单/依赖锁摘要；宿主与原生输入在后续 prepare:apk 才真正复制冻结，因此批准开始后也必须停止源码并行修改直至副本准备结束。

## 完成后应收集的输出

- `<run>/run.json`：各阶段状态；不能手填 succeeded。
- `<run>/apk-input-manifest.json`：冻结源输入，确认包含上述四文件及新的 Android 配置。
- `<run>/www-expected-manifest.json`：入口映射与所有 www bytes/hash。
- `<run>/android-staging-manifest.json`：cap sync 后通过的 exact files/config/plugins。
- `<run>/verify-apk.json`：ZIP/assets、应用标识与必要原生类的校验报告。
- `<run>/apk-signature.txt`：实际开发包签名验证输出。
- `<run>/瀚海-debug-<buildId>.apk`：仅全部通过才复制的候选；脚本输出 SHA256。

仍需单独真机验收：API28/29 与 API30+/35/36，横竖方向策略、cutout、手势/三键、滑动临时显示栏、后台/焦点恢复、键盘开关及保存导出。APK 静态校验不证明 UI 或沉浸运行时效果。
